## 1. ACCEPTANCE CRITERIA (AC) & BUSINESS RULE CONTRACT MAPPING

- **AC1 (Full Room Details & OpenAPI getRoomDetail Contract — H1, H2, H3):**
  - Endpoint: `GET /api/rooms/{id}?campusId={campusId}`
  - Schema strictly conforms to `docs/api/openapi.yaml` (`getRoomDetail` / `RoomDetailDto`):
    - `id`, `title`, `description`, `monthlyRentVnd`, `depositVnd`, `areaM2`, `roomType` (canonical OpenAPI names, no aliases).
    - `address`: Structured `AddressDto` (`addressLine`, `ward`, `district`) + `location`: `GeoPointDto` (`latitude`, `longitude`).
    - `distanceKm`: Dynamically computed from room coordinates to resolved campus via `HaversineDistanceCalculator` rounded to 1 decimal place (BR-SRCH-03).
    - `utilities`: `UtilitiesView` calculated strictly per BR-LST-03 (`PerPerson` × occupants, `Included` -> 0, `PerCubicMeter` × 4 m³). Zero mock/invented defaults.
    - `safety`: `SafetyDto` calculated from confirmed safety features per BR-LST-08. Empty array when none confirmed.
    - `photos`: List of `PhotoDto` (`id`, `kind`, `thumbUrl`, `mediumUrl`, `originalUrl`, `sortOrder`).
    - `houseRules`: `HouseRulesDto` (`versionNumber`, `updatedAtUtc`, `guestPolicy`, `cookingPolicy`, `parkingAvailable`, `guestPolicyNote`). Null when no rules declared.
    - `landlord`: Structured `LandlordContactDto` (`id`, `displayName`, `isVerified`, `memberSinceUtc`, `phoneNumber`, `zaloUrl`).
    - `status`: `ListingStatus` enum (`Available`, `Rented`, `Unpublished`, etc.).
    - `isVerified`: Boolean flag.
    - `lastUpdatedAtUtc`: UTC timestamp from aggregate.
    - Additional fields: `maxOccupants`, `furnishing`, `availableFrom` (date format `yyyy-MM-dd`), `isFavourite: false`, `publishedAtUtc`.
- **AC2 (Listing Status & Lifecycle Visibility — BR-LST-04a, M1):**
  - Publicly visible states on detail page: `Available`, `Rented`, `Unpublished`.
  - Non-public states: `PendingReview`, `Rejected`, `Suspended` return `404 Not Found` with ProblemDetails `errorCode: "ROOM_NOT_FOUND"`.
- **AC3 (Dedicated Similar Rooms Endpoint & BR-LST-10 Algorithm — M2):**
  - Dedicated Endpoint: `GET /api/rooms/{id}/similar?campusId={campusId}` (`getSimilarRooms`).
  - Algorithm (`GetSimilarRoomsUseCase`):
    1. **Target Validation:** If target room does not exist or is not publicly visible, returns 404 `ROOM_NOT_FOUND`.
    2. **Campus Validation:** Resolves campus via `ICampusRepository`. Unknown campus throws `DomainValidationException` (400 `CAMPUS_NOT_FOUND`).
    3. **Rent Threshold:** Monthly rent within ±20% of target room (`[0.8 * rent, 1.2 * rent]`).
    4. **Proximity Filter:** Distance between target room and candidate room $\le 2.0\text{ km}$ via Haversine.
    5. **Database Filter:** Prefiltered at SQL datastore level via bounding box and rent range (`IRoomSearchReadModel.QueryCandidatesAsync`) rather than in-memory full-table scan.
    6. **Type Prioritization & Fallback:** Prioritizes candidates with same `RoomType`. If fewer than 2 candidates share the same room type, relaxes type filter.
    7. **Card Distance Semantics:** `distanceKm` in returned `RoomCardDto` represents distance to requested campus per OpenAPI schema, while ranking orders by proximity to target room.
    8. **Ordering & Limit:** Ordered ascending by distance to target room, then by candidate ID; max 5 rooms returned.
- **AC4 (Landlord Phone Privacy — BR-AUTH-07):**
  - Only authenticated users (`IsAuthenticated == true`) receive plain unmasked `phoneNumber` and `zaloUrl`.
  - Anonymous/guest callers receive `null` for both `phoneNumber` and `zaloUrl` to prevent data scraping.

## 2. DEFENSIVE ARCHITECTURAL DESIGN & GUARDRAILS

### 2.1. Standardized Campus Resolution (M1, BR-CMP-01..03)
- Injected `ICampusRepository` across `GetRoomDetailUseCase` and `GetSimilarRoomsUseCase`.
- Unknown `campusId` explicitly throws `DomainValidationException($"Campus with ID '{id}' not found.", ProblemCodes.CampusNotFound)` mapped to HTTP 400 ProblemDetails.
- Empty/omitted `campusId` resolves default campus (`ICTU`) via `_campusRepository.GetDefaultCampusAsync(ct)`.
- Eliminates hardcoded campus registries or silent fallbacks.

### 2.2. ADR-012 §6 Weak Body Hash ETag Caching (H6)
- Cache ETag is weak (`W/"<sha256-hex>"`), computed from SHA-256 hash of the caller's serialized response body JSON.
- Guaranteed header pairing:
  - `ETag: W/"<hash>"`
  - `Cache-Control: private, no-cache`
  - `Vary: Authorization` (prevents cross-user cache collisions between guests and authenticated users).
- Supports RFC 9110 compliant conditional revalidation (`If-None-Match`, wildcard `*`, unquoted tokens), returning `304 Not Modified`.

### 2.3. Utility Estimation Formula (BR-LST-03 / H3)
- `ElectricityPriceVndPerKwh`: 100 kWh × rate.
- `WaterPriceVnd`:
  - `PerPerson`: rate × 1 person.
  - `Included`: 0 VND added to total.
  - `PerCubicMeter` (or default): rate × 4 m³.
- Unspecified utility items contribute 0 VND, without fabricating non-existent prices.

### 2.4. Production Datastore Wiring & Seed Hygiene (H4)
- SQLite datastore seeds sample rooms only when in `Development` environment or when `Sqlite:SeedDemoRooms = true`.
- Campuses reference data is always seeded across all environments (BR-CMP-01).
- Landlord contact information (`fullName`, `phoneNumber`, `isVerified`, `createdAtUtc`) joined directly from `Users` table (H2).

### 2.5. Domain Aggregates & Invariant Protection (M3, M4)
- `Room` aggregate constructor enforces all BR-LST-01 creation invariants via `EnsureInvariants()`.
- Mutators for concurrency token are `internal` (`GUARDRAILS §1.5.2`).
- All compatibility accessors (`Price`, `MonthlyRent`, `DepositAmount`, `Area`, `AreaSquareMeters`, `Address`, `LastUpdatedAt`) removed in favor of canonical DDD properties.
