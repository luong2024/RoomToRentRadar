## 1. ACCEPTANCE CRITERIA (AC) & CONTRACT MAPPING

- **AC1 (Full Room Details & OpenAPI getRoomDetail Contract — H1):**
  - Endpoint: `GET /api/rooms/{id}?campusId={campusId}`
  - Schema complies with `docs/api/openapi.yaml` (`getRoomDetail`):
    - `id`, `title`, `description`, `monthlyRent`, `depositAmount`, `areaSquareMeters`, `roomType`
    - `location`: Structured `AddressDto` (fullAddress, ward, district, city) + `GeoPointDto` (latitude, longitude)
    - `distanceKm`: Dynamically computed from room coordinates to specified `campusId` (ICTU default, TNUS, SFL, TUEBA, TUAF, TNUE) via Haversine formula (BR-CMP-03).
    - `utilities`: `UtilitiesView` (included, electricityCost, waterCost, internetCost).
    - `safety`: `SafetyDto` (hasFireExtinguisher, hasEmergencyExit, hasCctv).
    - `photos`: List of `PhotoDto` (id, url, caption, isCover, displayOrder).
    - `houseRules`: `HouseRulesDto` (curfew, allowPets, allowCooking, maxOccupants, additionalRules).
    - `landlord`: Structured `LandlordContactDto` (name, phoneNumber, isVerified, responseRate).
    - `status`: `ListingStatus` enum (`Available`, `Rented`, `Unpublished`, etc.).
    - `isAvailable`: Boolean flag.
    - `lastUpdatedAtUtc`: UTC timestamp.
- **AC2 (Listing Status & Lifecycle Visibility — BR-LST-04a, M1):**
  - Publicly visible states on detail page: `Available`, `Rented`, `Unpublished`.
  - Non-public states: `PendingReview`, `Rejected`, `Suspended` return `404 Not Found` with ProblemDetails `errorCode: "ROOM_NOT_FOUND"`.
- **AC3 (Dedicated Similar Rooms Endpoint & BR-LST-10 Algorithm — H2):**
  - Dedicated Endpoint: `GET /api/rooms/{id}/similar` (`getSimilarRooms`).
  - Algorithm (`SimilarRoomsPolicy`):
    1. **Availability Filter:** Only listings with `ListingStatus.Available` are candidates.
    2. **Self-Exclusion:** Excludes target room itself (`Id != targetRoomId`).
    3. **Rent Threshold:** Monthly rent within ±20% of target room (`[0.8 * rent, 1.2 * rent]`).
    4. **Proximity Filter:** Distance between target room and candidate room $\le 2.0\text{ km}$ via Haversine.
    5. **Type Prioritization & Fallback:** Prioritizes candidates with same `RoomType`. If fewer than 2 candidates share the same room type, includes candidates of other room types satisfying the spatial & rent criteria.
    6. **Ordering & Limit:** Ordered ascending by distance to target room; max 5 rooms returned.
- **AC4 (Landlord Phone Privacy — BR-AUTH-07):**
  - Only authenticated users (`IsAuthenticated == true`) receive plain unmasked `phoneNumber`.
  - Anonymous callers receive masked phone number (`"0988***456"`) or `null` to prevent data scraping.

## 2. DEFENSIVE DOMAIN DESIGN & ARCHITECTURAL GUARDRAILS

### 2.1. Aggregate Lifecycle & State Transitions (ADR-011 / M1, M3)
- `Room` aggregate located in `RoomToRentRadar.Domain.Aggregates.Room`.
- Explicit lifecycle state machine methods:
  - `Publish()`: `PendingReview` -> `Available`
  - `MarkAsRented()`: `Available` -> `Rented`
  - `MarkAsAvailable()`: `Rented` -> `Available`
  - `Unpublish(reason)`: Valid states -> `Unpublished`
  - `Reject(reason)`: `PendingReview` -> `Rejected`
  - `Suspend(reason)`: Valid states -> `Suspended`
- Invalid transitions throw `InvalidStateTransitionException` (ADR-011).

### 2.2. Domain Invariants Self-Protection (Guardrail 1.5.3 / M3)
- `MonthlyRent > 0` and `DepositAmount >= 0`.
- `AreaSquareMeters` constrained between $5.0\text{ m}^2$ and $200.0\text{ m}^2$ (rejects NaN, Infinity, negative values).
- Coordinates strictly bounded within Vietnam territory (`Latitude`: [8.0, 24.0], `Longitude`: [102.0, 110.0]).
- Collections (`Amenities`, `PhotoUrls`, `HouseRules`) clone arrays to prevent external reference mutation.
- `ConcurrencyToken` declared and tracked on aggregate root.

### 2.3. Caching & Error Handling (ADR-004, ADR-012 / M2)
- HTTP ETag header generated based on room ID and UTC timestamp: `"{id}_{ticks}"`.
- Handles `If-None-Match` client header; returns `304 Not Modified` when ETag matches.
- ProblemDetails conforms to RFC 7807 with standardized `errorCode` extension:
  - `ROOM_NOT_FOUND` (404)
  - `VALIDATION_FAILED` (400)

### 2.4. Production Datastore Wiring (GUARDRAILS §1.5.4, ADR-002 / H3)
- Registered `SqliteRoomRepository` as primary implementation in `AddSqliteDatastore`.
- SQLite `Rooms` table schema updated with `Status`, `LandlordName`, and `LandlordPhoneNumber` columns.
- `InMemoryRoomRepository` used strictly in unit tests and development fallback.

## 3. COMPONENT INVENTORY & ARTIFACTS

### 3.1. Domain Layer (`RoomToRentRadar.Domain`)
- `Aggregates/Room.cs`: DDD aggregate root with invariants and state transition methods.
- `Enums/ListingStatus.cs`: `PendingReview`, `Available`, `Rented`, `Unpublished`, `Suspended`, `Rejected`.
- `Enums/RoomType.cs`: `BoardingRoom`, `Studio`, `SharedHouse`, `Apartment`.
- `Enums/Amenity.cs`: Standardized amenities flags/enums.
- `Policies/SimilarRoomsPolicy.cs`: Domain specification implementing BR-LST-10 similarity logic.
- `Exceptions/InvalidStateTransitionException.cs`: Domain transition violation.

### 3.2. Ports Layer (`RoomToRentRadar.Ports`)
- `Contracts/Responses/Rooms/RoomDetailDto.cs`: OpenAPI-compliant immutable record.
- `Contracts/Responses/Rooms/AddressDto.cs`, `GeoPointDto.cs`, `UtilitiesView.cs`, `SafetyDto.cs`, `PhotoDto.cs`, `HouseRulesDto.cs`, `LandlordContactDto.cs`.
- `Contracts/Responses/Rooms/RoomCardDto.cs`: Card DTO for similar rooms response.
- `Inbound/UseCases/Rooms/IGetRoomDetailUseCase.cs`: Single execution driving port (`ExecuteAsync(id, ct, campusId)`).
- `Inbound/UseCases/Rooms/IGetSimilarRoomsUseCase.cs`: Single execution driving port for similar rooms.
- `Outbound/Repositories/IRoomRepository.cs`: Core repository port.
- `Outbound/Repositories/IRoomSearchReadModel.cs`: Read-model port for spatial & filter search.

### 3.3. Application Layer (`RoomToRentRadar.Application`)
- `UseCases/Rooms/GetRoomDetailUseCase.cs`: Fetches room, checks visibility per BR-LST-04a, calculates campus distance per BR-CMP-03, and applies phone privacy per BR-AUTH-07.
- `UseCases/Rooms/GetSimilarRoomsUseCase.cs`: Implements BR-LST-10 multi-criteria similar room search.
- `Mappers/RoomMapper.cs`: Bidirectional mapper between `Room` aggregate and OpenAPI DTOs.

### 3.4. Datastore & Infrastructure (`RoomToRentRadar.Datastore.Sqlite` & `Infrastructure`)
- `Context/SqliteDbContext.cs`: Table DDL and seed logic with `Status` and landlord info.
- `Repositories/SqliteRoomRepository.cs`: Production SQLite implementation.
- `Adapters/Mocks/InMemoryRoomRepository.cs`: Test mock adapter.

### 3.5. Web API Layer (`RoomToRentRadar.Api`)
- `Controllers/RoomsController.cs`:
  - `GET /api/rooms/{id}`: Detail endpoint with ETag, 304, dynamic `campusId`, ProblemDetails.
  - `GET /api/rooms/{id}/similar`: Dedicated similar rooms endpoint per OpenAPI contract.
- `Program.cs`: `WebApplicationFactory` support via `public partial class Program`, string enum converter, `InvalidModelStateResponseFactory`.
