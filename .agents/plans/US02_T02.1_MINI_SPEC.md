## 1. ACCEPTANCE CRITERIA (AC) & BUSINESS RULE CONTRACT MAPPING

- **AC1 (Full Room Details & OpenAPI getRoomDetail Contract):**
  - Endpoint: `GET /api/rooms/{roomId}?campusId={campusId}` (aligned with `openapi.yaml` §operationId: getRoomDetail).
  - Schema strictly conforms to `docs/api/openapi.yaml` (`getRoomDetail` / `RoomDetailDto`):
    - `id`, `title`, `description`, `monthlyRentVnd`, `depositVnd`, `areaM2`, `roomType`.
    - `address`: Structured `AddressDto` (`addressLine`, `ward`, `district`) + `location`: `GeoPointDto` (`latitude`, `longitude`).
    - `distanceKm`: Dynamically computed from room coordinates to resolved campus via `HaversineDistanceCalculator` rounded to 1 decimal place (`BR-SRCH-03`).
    - `utilities`: `UtilitiesView` calculated strictly per `BR-LST-03` and `openapi.yaml:1459` (`PerPerson`: 1 × price, `Included`: 0, `PerCubicMeter`: 4 m³ × price). Zero mock/invented defaults.
    - `safety`: `SafetyDto` calculated from confirmed safety features per `BR-LST-08`. Empty array when none confirmed.
    - `photos`: List of `PhotoDto` (`id`, `kind`, `thumbUrl`, `mediumUrl`, `originalUrl`, `sortOrder`).
    - `houseRules`: `HouseRulesDto` (`versionNumber`, `updatedAtUtc`, `guestPolicy`, `cookingPolicy`, `parkingAvailable`, etc.). Null when no rules declared.
    - `landlord`: Structured `LandlordContactDto` (`id`, `displayName`, `isVerified`, `memberSinceUtc`, `phoneNumber`, `zaloUrl`).
    - `status`: `ListingStatus` enum (`Available`, `Rented`, `Unpublished`, etc.).
    - `isVerified`: Boolean flag (`VerifiedAtUtc != null`).
    - `lastUpdatedAtUtc`: UTC timestamp from aggregate.
- **AC2 (Listing Status & Lifecycle Visibility — BR-LST-04a):**
  - Publicly visible states on detail page: `Available`, `Rented`, `Unpublished` (HTTP 200).
  - Non-public states: `PendingReview`, `Rejected`, `Suspended` return `404 Not Found` with ProblemDetails `errorCode: "ROOM_NOT_FOUND"` for guests / non-owners; owners (`UserId == room.LandlordId`) and Admins receive `200 OK`.
- **AC3 (Dedicated Similar Rooms Endpoint & BR-LST-10 Algorithm — Anti-IDOR):**
  - Dedicated Endpoint: `GET /api/rooms/{roomId}/similar?campusId={campusId}` (`getSimilarRooms`).
  - Algorithm (`GetSimilarRoomsUseCase`):
    1. **Target Validation & Anti-IDOR (BR-LST-04a / GUARDRAILS §1.5.6):** If target room does not exist, or has hidden status (`PendingReview`, `Rejected`, `Suspended`) and caller is not owner/Admin, returns 404 `ROOM_NOT_FOUND`.
    2. **Campus Validation:** Resolves campus via `ICampusRepository`. Unknown campus throws `DomainValidationException` (400 `CAMPUS_NOT_FOUND`).
    3. **Rent Threshold:** Monthly rent within ±20% of target room (`[0.8 * rent, 1.2 * rent]`).
    4. **Proximity Filter:** Distance between target room and candidate room ≤ 2.0 km via Haversine.
    5. **Database Filter:** Prefiltered at SQL datastore level via bounding box and rent range (`IRoomSearchReadModel.QueryCandidatesAsync`).
    6. **Type Prioritization & Fallback:** Prioritizes candidates with same `RoomType`. If fewer than 2 candidates share the same room type, relaxes type filter.
    7. **Card Distance Semantics:** `distanceKm` in returned `RoomCardDto` represents distance to requested campus per OpenAPI schema, while ranking orders by proximity to target room.
    8. **Ordering & Limit:** Ordered ascending by distance to target room, then by candidate ID; max 5 rooms returned.
- **AC4 (Landlord Phone Privacy — BR-AUTH-07):**
  - Authenticated users (`IsAuthenticated == true`) receive plain unmasked `phoneNumber` and `zaloUrl`.
  - Anonymous/guest callers receive `null` for both `phoneNumber` and `zaloUrl` to prevent data scraping.
- **Non-Functional: Weak ETag Caching (ADR-012 §6):**
  - Weak ETag validator `W/"<hash>"` computed from caller-specific JSON response body.
  - Headers: `Cache-Control: private, no-cache` and `Vary: Authorization`.
  - Revalidation via `If-None-Match`: Returns `304 Not Modified` on match.
- **Fail-Fast Production DI (GUARDRAILS §1.5):**
  - `RoomsController` production constructor `[ActivatorUtilitiesConstructor]` requires all use cases without null defaults, failing fast at application startup if registration is missing.
