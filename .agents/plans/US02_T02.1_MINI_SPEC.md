## 1. ACCEPTANCE CRITERIA (AC) MAPPING & VERIFICATION

- **AC1 (Full Room Details):** Returns description, monthly rent, deposit amount, area, room type, amenities, full address, landlord name, photos, 360° panorama URL, and house rules.
  - *Verification:* Verified via `GetRoomDetailUseCaseTests` and `RoomDetailEndpointIntegrationTests`.
- **AC2 (Listing Status & Timestamp):** Returns listing status (`Status`: "Available", "Unavailable", "Rented", "PendingVerification"), `IsAvailable` boolean, and last-updated timestamp (`LastUpdatedAt`).
  - *Verification:* Verified via `GetRoomDetailUseCaseTests` and `RoomMapperTests`.
- **AC3 (Unavailable / Rented Handling & Similarity Definition):**
  - When a room is `Unavailable` or `Rented`, the API responds with a polite notification message (`UnavailableMessage`) and suggests available similar rooms nearby (`SimilarRooms`).
  - **Similarity Definition (H1, M1):**
    1. **Availability Filter:** Only rooms with `Status == RoomStatus.Available` are candidates.
    2. **Self-Exclusion:** The requested room itself (`Id == excludeRoomId`) is excluded.
    3. **Ranking Criteria:** Ranked primarily by proximity to campus (`|DistanceToCampusKm - targetDistanceKm|`), then by price delta (`|MonthlyRent - targetRent|`), and then by area delta (`|AreaSquareMeters - targetArea|`).
    4. **Limit:** Maximum 3 similar rooms returned.
  - *Verification:* Verified via `InMemoryRoomRepositoryTests`, `GetRoomDetailUseCaseTests`, and `RoomDetailEndpointIntegrationTests`.
- **AC4 (Landlord Phone Privacy):**
  - Only authenticated users (`IsAuthenticated == true`) can view `LandlordPhoneNumber`.
  - Anonymous / guest callers receive `null` to prevent data harvesting.
  - *Verification:* Verified via `GetRoomDetailUseCaseTests` and `RoomDetailEndpointIntegrationTests`.

## 2. DEFENSIVE DOMAIN DESIGN & ARCHITECTURAL GUARDRAILS

### 2.1. Concurrency Control (Guardrail 1.5.2 / H2)
- `Room` entity declares `public string ConcurrencyToken { get; private set; }` and `SetConcurrencyToken(string?)` to support optimistic concurrency control on evolving listing states.
- Architecture test `DomainAggregatesAndMutableEntities_MustDeclareConcurrencyTokenProperty` validates that all mutable entities enforce concurrency tokens.

### 2.2. Invariant Self-Protection (Guardrail 1.5.3 / H3)
- `MonthlyRent <= 0`: Rejects 0 and negative prices with `DomainValidationException`.
- `AreaSquareMeters <= 0`: Rejects 0 and negative areas with `DomainValidationException`.
- `DepositAmount < 0`: Rejects negative deposits (0 deposit allowed).
- `RoomStatus`: Rejects invalid enum integers via `Enum.IsDefined(typeof(RoomStatus), status)`.
- **Defensive Copying:** Caller collections for `Amenities`, `PhotoUrls`, and `HouseRules` are cloned via `.ToArray()` to prevent external reference mutation.

### 2.3. Least Privilege & Moderation Protection (Guardrail 1.5.6 / M4)
- Listings with `Status == RoomStatus.PendingVerification` are not publicly visible (`!room.IsPubliclyVisible`).
- Querying an unverified room returns `null` (mapped to HTTP `404 Not Found`) so unapproved contact and location details are never leaked to public users.

## 3. COMPONENT INVENTORY & ARTIFACTS

### 3.1. Domain Layer (`RoomToRentRadar.Domain`)
- `Entities/Room.cs`: Encapsulated domain entity with invariants, defensive copy, and concurrency token.
- `Enums/RoomStatus.cs`: `Available`, `Unavailable`, `Rented`, `PendingVerification`.

### 3.2. Ports Layer (`RoomToRentRadar.Ports`)
- `Contracts/Responses/Rooms/RoomCardDto.cs`: Summary DTO for room cards and similar room suggestions.
- `Contracts/Responses/Rooms/RoomDetailDto.cs`: Extended immutable record including `Status`, `IsAvailable`, `UnavailableMessage`, `SimilarRooms`. *(Shared Contract Trigger #3 documented for MAUI UI alignment).*
- `Inbound/UseCases/Rooms/IGetRoomDetailUseCase.cs`: Single-method driving port (`ExecuteAsync`).
- `Outbound/Repositories/IRoomRepository.cs`: Driven port for room data access with documented contract semantics and distance support.
- `Outbound/ExternalServices/ICurrentUserContextPort.cs`: Driven port for user security context (naming convention compliant).
- `Outbound/Security/ICurrentUserContext.cs`: Backwards-compatible alias port.

### 3.3. Application Layer (`RoomToRentRadar.Application`)
- `UseCases/Rooms/GetRoomDetailUseCase.cs`: Single-purpose use case enforcing whitespace trimming, moderation privacy, authenticated phone masking, and distance-based similarity query.
- `Mappers/RoomMapper.cs`: Explicit enum mapping (`MapRoomStatus`) protecting contract stability.
- `DependencyInjection.cs`: Registers `IGetRoomDetailUseCase` -> `GetRoomDetailUseCase`.

### 3.4. Infrastructure Layer (`RoomToRentRadar.Infrastructure`)
- `Adapters/Mocks/InMemoryRoomRepository.cs`: Thread-safe mock repository with ICTU seed data, multi-criteria similarity sorting, and `internal AddOrUpdate`.
- `Adapters/Mocks/InMemoryCurrentUserContext.cs`: Mock user context for tests.
- `DependencyInjection.cs`: Binds `IRoomRepository` and fallback `ICurrentUserContextPort` with `[US02/T02.2]` migration marker.

### 3.5. Web API Layer (`RoomToRentRadar.Api`)
- `Controllers/RoomsController.cs`: REST Controller exposing `GET /api/rooms/{id}`.
  - Returns `200 OK` on success.
  - Returns `400 Bad Request` with ProblemDetails when `id` is null, empty, or whitespace.
  - Returns `404 Not Found` with ProblemDetails when room is not found or pending verification.
- `Security/HttpContextUserContextAdapter.cs`: Production adapter implementing `ICurrentUserContextPort`.
- `Program.cs`: Wires `ICurrentUserContextPort` to `HttpContextUserContextAdapter`.
